[IMPORTANT]
====
The `setup-tas-environment.sh` helper baked into the terminal image still points the OIDC variables at the old `trusted-artifact-signer` realm. RHADS 1.8 moved the signing client into `{keycloak_realm_name}` and pointed Fulcio there, so that is now the only issuer Fulcio will accept. The helper also writes the variables to `~/.bashrc`, so every new terminal - and every re-run of the helper - brings the stale realm back.

Until the image is rebuilt, repoint them yourself. This is safe to run as often as you like:

[source,bash,role=execute,subs=attributes+]
----
export OIDC_ISSUER_URL="${OIDC_ISSUER_URL%/realms/*}/realms/{keycloak_realm_name}"
export COSIGN_OIDC_ISSUER="$OIDC_ISSUER_URL"
export COSIGN_CERTIFICATE_OIDC_ISSUER="$OIDC_ISSUER_URL"
export SIGSTORE_OIDC_ISSUER="$OIDC_ISSUER_URL"
git config --global gitsign.issuer "$OIDC_ISSUER_URL"
echo "$OIDC_ISSUER_URL"
----

Skip it and the login URL `cosign` and `gitsign` hand you still works - the old realm is still served, so you will log in and get a token back. Fulcio then refuses the token, because the issuer it names is not the one Fulcio trusts. Verification fails too - including the commands that pass no issuer flag at all, because `cosign` falls back to `COSIGN_CERTIFICATE_OIDC_ISSUER`:

[source,console]
----
Error: ... none of the expected identities matched what was in the certificate,
got subjects [user1@demo.redhat.com] with issuer
"https://sso.{openshift_cluster_ingress_domain}/realms/{keycloak_realm_name}",
expected issuer value
"https://sso.{openshift_cluster_ingress_domain}/realms/trusted-artifact-signer"
----
