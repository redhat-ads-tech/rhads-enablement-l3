[NOTE]
====
Two things are worth noticing, both consequences of the move to `cosign` 3.x.

The signature now shows up as a second *attestation*, with the predicate type `https://sigstore.dev/cosign/sign/v1` alongside the SLSA provenance - the same two artifact types `cosign tree` listed as OCI referrers earlier.

More importantly, the report no longer carries the signing certificate, its chain, or the identity metadata derived from it. Earlier `ec` versions embedded the PEM and a decoded `Issuer`, `Subject Alternative Name` and so on for each signature; those fields are simply absent now, and the `signatures` entries come back empty. If you want the signing identity, read it off the certificate in the signature bundle yourself rather than expecting `ec` to surface it.
