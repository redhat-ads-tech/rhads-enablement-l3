[NOTE]
====
Two things are worth noticing in this report, and one thing about reports in general.

The image signature and the attestation are reported separately. The signature sits in the component's `signatures` array, while `attestations` lists only the SLSA provenance attached earlier - even though `cosign tree` presented both as OCI referrers of the same image.

The report does not carry the signing certificate, its chain, or the identity metadata derived from them. Earlier `ec` versions embedded the PEM and a decoded `Issuer`, `Subject Alternative Name` and so on for each signature; those fields are absent. If you want the signing identity, read it off the certificate in the signature bundle rather than expecting `ec` to surface it.

The shape of this report tracks the `ec` version, which the report itself records as `ec-version` near the end. The capture above is from `v0.9.132+redhat`; a different build may group or label these fields differently, so treat the layout as illustrative and the `successes` codes as the part that matters.
